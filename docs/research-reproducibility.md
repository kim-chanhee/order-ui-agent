# 논문 기술과 재현 범위

## 현재 구현을 설명하는 문장

> 두 조건은 동일한 자연어 요청 분류기, 구조화된 분석 계획 생성기, 스키마 탐색 및 SQL 검증·실행 계층을 공유한다. Baseline은 사용자 검토 없이 계획을 실행하고, Agent2UI는 구조화된 계획을 표시하여 사용자가 수정·확정한 후 실행한다. 일반 조회에는 LLM 기반 SQL 생성을 사용하며, 사전에 등록된 모집단·부분집합 지표에는 두 조건에 동일한 설정 기반 SQL 컴파일러를 적용한다.

등록 지표가 사용된 실행을 전부 “LLM이 SQL을 생성했다”고 표현하면 현재 구현과 다릅니다. `execution_route`로 `fast_llm_sql`과 `registered_metric`을 구분합니다. `llm_model_calls`는 SQL 실행 단계의 호출 수이며, 전체 라우팅·계획 생성 호출 수를 뜻하지 않습니다.

## 비교 조건에서 유지할 사항

- 동일 데이터 프로필, DB 스냅샷, 모델·프롬프트·검증 규칙·등록 지표·실행 제한을 적용합니다.
- 모드 간 주요 차이는 계획 검토·수정·확정 단계입니다. 한 모드에만 정답 SQL, 보조 자료 또는 우회 경로를 주지 않습니다.
- 등록 지표는 평가 전에 업무 정의로 고정하고, 논문에 사전 제공 지식으로 기술합니다. 이번처럼 실패 사례를 보고 변경한 데이터·질문은 개발용 검증 사례이며 미사용 평가셋의 증거가 아닙니다.
- 평가 중 규칙·모델·프로필을 변경하면 버전을 구분해 다시 실행합니다. 이전 참가자 결과를 새 구현 결과로 바꾸지 않습니다.
- 실패·0행·판단 불가·실행 전 확인 질문을 구분합니다. SQL 실행 성공만으로 정답이라고 채점하지 않습니다.

## 기록과 데이터 분리

개발 검증 서버는 별도 상태·로그 경로를 사용합니다.

```bash
ORDER_UI_STATE_DB_PATH=artifacts/validation/runtime_state.sqlite \
ORDER_UI_LOG_DIR=artifacts/validation/logs \
PORT=8002 uv run order-ui-agent
```

참가자 ID·프로필을 보내지 않는 관리자 테스트는 참가자 실험 CSV에 기록하지 않습니다. 기존 참가자 로그·설문은 보존하고, 개발 결과는 `artifacts/validation/`에 둡니다. 프로필 사용 시에는 프로필의 상태 DB 경로가 개별 환경 변수보다 우선합니다.

재현 보고서에는 코드 버전/차이, 데이터 스냅샷 식별값, 비밀을 제외한 프로필과 모델 설정, 질문 순서, 계획/수정/확정, SQL, 결과 행, 오류, 지연 시간을 함께 보관해야 합니다. 현재 스키마/실행 식별값은 전체 데이터 내용의 암호학적 해시를 대신하지 않습니다. 공개 배포에는 원본 참가자 자료나 API 키를 포함하지 않습니다.

## 현재 검증 결과의 해석

2026-11-01 수정 과정에서 실제 질문을 재실행하던 중 API가 `credit_balance_exhausted`를 반환했습니다. 따라서 최종 수정 버전의 전체 모델 기반 과제 성공률은 아직 확정하지 않았습니다.

- 단위·회귀 테스트: 스키마/계획/검증/모드별 공통 실행/오류 처리.
- 원래 DB의 등록 지표 검증: 독립 정답 SQL과 7·14·30·60·90일 구간의 결과를 비교. 모델 호출 없이 실행.
- 다른 도메인 검증: 도서 DB의 전체 건수, 장르별 건수, 평균 가격, 저자 FK 조인과 합성 병동 데이터의 등록 비율. 모델 호출 없이 실행.
- 실제 모델 기반 전체 질문 흐름: API 잔액 복구 후 재실행 필요.

이 결과는 사용자 경험 개선이나 통계적 유의성을 증명하지 않습니다. 새 데이터에서 자동으로 항상 정답을 낸다는 주장도 뒷받침하지 않습니다. 현재 UI 전송 모델을 외부 A2UI 표준과 완전히 호환된다고 기술하지 않습니다.

## 재검증 명령

```bash
uv run pytest tests -q
node --test tests/js/review-plan.test.js
PYTHONPATH=. uv run python scripts/validate_registered_metrics.py
```

마지막 명령은 기존 주문 DB와 평가용 정답 파일이 있을 때 사용하는 로컬 실행 검사입니다. 실제 모델 재검증은 잔액을 복구한 뒤 별도 검증 서버에 연결합니다.

```bash
TASK_TEST_BASE_URL=http://127.0.0.1:8002 \
TASK_TEST_OUTPUT_DIR=artifacts/validation/live-replay \
PYTHONPATH=. uv run python scripts/validate_task_flows.py
```

순차 질문은 과제 안에서 같은 대화를 유지하고 과제·모드 사이에는 새 대화를 만듭니다. 계획을 정답에 맞춰 자동 수정하지 않습니다. 마지막 미수령 0행은 선행 고객 선택과 물품 범위가 맞는지 SQL을 별도 검토해야 하며 자동으로 통과 처리하지 않습니다. 개발용 정답 파일은 평가 스크립트만 읽으며 실행기의 검색/답변 근거로 사용하지 않습니다.
